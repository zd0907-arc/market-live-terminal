# Codex Agent 调用手册

> 文档职责：本文是默认调度、模型升级条件和用户交互方式的准绳。Agent 名册见 `registry/README.md`；文档地图见 `DOCS_INDEX.md`；单个 Agent 的详细定义见 `agents/*.md`；单公司/行业流程分别见 `workflows/company-research.md` 和 `workflows/industry-research.md`。

## 这个文件解决什么

你不需要在系统页面里点按钮，也不需要理解复杂工程配置。你只要在 Codex 对话里提出研究任务，主控就按这里的规则决定调用哪些 Agent，让它们各自独立干活，再把结果汇总给你。

一句话目标：

> 把 10 个金融 Agent 做成 Codex 对话里的研究团队，而不是前端功能，也不是固定 skill SOP。

## Agent 名册

Agent 编号、中文名、来源、状态和默认模型以 `registry/README.md` 为准。本文只记录主控在不同研究任务下如何调用这些 Agent。

## 主控怎么调用

主控就是当前 Codex 会话里的我。我的职责是调度，不是代替所有 Agent 写完。

当你提出任务时，我按下面方式处理：

1. 先判断这是单公司、行业/赛道、模型训练辅助，还是全新领域研究。
2. 先叫 `02 任务拆解与研究 Brief Agent`，让它拆任务和判断需要哪些 Agent。
3. 根据任务类型派出一批独立子 Agent。
4. 子 Agent 各自查本地数据和免费公开资料，各自输出结论和缺口。
5. 叫 `07 事实一致性对账 Agent` 检查冲突、来源和口径。
6. 如果某个 Agent 结果不合格，我把它打回重写。
7. 最后叫 `01 研究总签 Agent` 汇总成你看的研究结果。
8. 如果需要沉淀到项目里，再叫 `08 研究收口与晋级 Agent`。
9. 如果需要进入选股页或公司详情页，再叫 `11 研究页面生成 Agent` 生成页面产物。

## 单公司研究默认调度

比如你说：

```text
用这 10 个 Agent 研究振德医疗。
```

默认流程是：

1. `02 任务拆解与研究 Brief Agent`
   - 明确公司、代码、研究重点和成功标准。
   - 对单公司研究，默认把“公司做什么、收入/利润来源、股价跟什么走”列为成功标准。

2. 第一批独立 Agent：
   - `03 财报与管理层信号 Agent`
   - `05 市场与行业研究 Agent`
   - `09 财务质量审查 Agent`
   - `10 实体、监管与舆情风险 Agent`

3. 第二批依赖型 Agent：
   - `04 轻量财务建模 Agent`
   - `06 估值与股价驱动核查 Agent`

4. 质检和汇总：
   - `07 事实一致性对账 Agent`
   - 必要时打回前面的 Agent 重写
   - `01 研究总签 Agent`
   - `08 研究收口与晋级 Agent`
   - 如要给页面使用：`11 研究页面生成 Agent`

## 行业/热点赛道研究默认调度

比如你说：

```text
研究最近 A 股医疗耗材方向的机会和风险。
```

默认流程是：

1. `02 任务拆解与研究 Brief Agent` 定义赛道边界。
2. `05 市场与行业研究 Agent` 做主研究。
3. `10 实体、监管与舆情风险 Agent` 查政策和监管。
4. `03 财报与管理层信号 Agent` 抽样看代表公司。
5. `09 财务质量审查 Agent` 抽样看代表公司质量。
6. `06 估值核查 Agent` 看行业估值位置。
7. `07 事实一致性对账 Agent` 做口径检查。
8. `01 研究总签 Agent` 形成赛道研究结论。

## 全新领域研究默认调度

比如你说：

```text
研究一个我还不熟的新方向，看看 A 股有没有相关公司。
```

默认流程是：

1. `02 任务拆解与研究 Brief Agent` 先把领域拆成概念、产业链和关键词。
2. `05 市场与行业研究 Agent` 找产业链、政策、需求和公司映射。
3. `10 实体、监管与舆情风险 Agent` 查监管和风险。
4. 如能映射到 A 股公司，再调用 `03`、`09`、`06`。
5. 如果还只是概念阶段，不强行做财务模型和估值。

## Agent 独立性的要求

为了避免退回到“主控自己写完整报告”，以后正式 run 要遵守：

- 每个被调用的 Agent 都要有自己的小结。
- 每个 Agent 只回答自己职责范围内的问题。
- 主控不能把某个 Agent 应该做的分析提前替它写完。
- Agent 之间可以互相引用结论，但要说明来自哪个 Agent。
- `07 事实一致性对账 Agent` 可以要求某个 Agent 重写。
- 最终报告要能看出哪些结论来自哪个 Agent。

## 单公司最终输出必须回答

每次正式单公司研究，最终报告必须先回答用户最关心的 6 个问题：

1. 这家公司是做什么的。
2. 收入构成是什么，按产品/地区/渠道拆。
3. 利润主要来自什么，是经营利润、非经常损益、汇兑、资产处置还是财务收益。
4. 财务基本盘如何，包括增长、现金流、应收、存货、减值、商誉、负债、分红和资本开支。
5. 过去股价主要跟什么走：行业主题、商品价格、地缘事件、政策、业绩兑现、资金风格还是公司事件。
6. 接下来最应该盯哪些变量。

固定模板见 `schemas/company-final-report-template.md`。

## 产出放哪里

短研究可以直接在 Codex 对话里给你结果。

正式研究建议同时落到：

```text
agentic_finance_agents/runs/<run_id>/
```

里面可以放：

- `00-brief.md`
- `agents/03-financial-signal.md`
- `agents/05-market-industry.md`
- `agents/09-financial-quality.md`
- `agents/10-risk-screening.md`
- `07-fact-check.md`
- `final-report.md`
- `close-pack.md`

这些还是临时研究产物，不自动进入正式库或页面。等你认可字段和格式后，再决定哪些内容沉淀到正式项目。

## 模型使用

- 每个独立 Agent 默认使用 `5.5 high`。
- 遇到复杂财务质量、估值冲突、政策影响、重大风险、打回重写时，可以升级 `5.5 xhigh`。
- 不默认给每个 Agent 再开子 Agent；只有材料特别多或冲突很复杂时再拆。

## 主控的选择规则

| 你的问题 | 优先调用 |
|---|---|
| 这家公司基本面怎么样 | 02、03、05、09、10、07、01 |
| 最近财报怎么看 | 03、09、04、07、01 |
| 利润质量好不好 | 09、03、07、01 |
| 所在行业/赛道怎么样 | 05、10、03、07、01 |
| 估值贵不贵 | 06、04、05、09、07、01 |
| 股价过去跟什么走 | 06、05、03、10、07、01 |
| 有没有雷 | 10、03、09、07、01 |
| 研究结果能不能进页面或数据库 | 08、07、01 |
| 研究结果怎么生成页面 | 11、08、07、01 |
| 能不能用于训练模型 | 08、07、05、09、10 |

## 估值研究的最低标准

用户问“贵不贵”时，不能只查一个当前 PE。`06` 必须至少回答：

1. 估值基准日、股价、市值。
2. 用上一完整年度利润算 PE。
3. 用 TTM 利润算 PE。
4. 用最新季度扣非净利机械年化算 PE，并明确这不是预测，只是分母变化压力测试。
5. 当前利润分母和上一年相比为什么变了。
6. 同业或行业中位数、区间或分位；拿不到就写缺口。
7. 估值变化是经营改善，还是临时高景气/一次性因素导致。

这些内容要进入 `06-valuation-reviewer.json` 和最终报告，供 `11` 做页面图表。

## 对用户的交互方式

你以后可以直接说：

```text
用 Agent 研究振德医疗，重点看利润质量和医疗耗材行业环境。
```

或者：

```text
派行业研究 Agent 研究一个 A 股热点赛道。
```

我需要做的是：

- 判断应该调用哪些 Agent。
- 启动独立子 Agent 或分批任务。
- 在过程中告诉你当前哪个 Agent 在干什么。
- 把各 Agent 的结果汇总给你。
- 明确哪些地方证据不足、需要打回、或者只能先观察。
