# 研究治理规则

## 结论

这里定义所有 Agent 共同遵守的研究规则。它不替代单个 Agent 的职责定义，而是约束研究能不能被信任、能不能进入页面或数据库。

## Agent 独立性

1. 被调用的 Agent 必须有自己的产物或可审阅结论。
2. Agent 只回答自己职责范围内的问题。
3. 主控不能把 10 个 Agent 的工作混成一篇报告后声称已经多 Agent 执行。
4. Agent 可以引用上游结论，但必须说明来自哪个 Agent。
5. `07` 可以打回任何事实不足、口径冲突或结论越界的 Agent。

## 证据规则

1. 关键事实必须有 `source_ref`。
2. 外部网页必须记录 URL、访问日期和引用范围。
3. 本地数据必须记录数据库、表、字段、查询口径或文件路径。
4. 无法取得的数据进入 `data_gaps`。
5. 不允许用模型记忆补财务、估值、股价或监管事实。

## 估值规则

估值研究不能只报当前 PE。`06` 至少需要：

1. 估值基准日、股价、市值。
2. 上一完整年度利润口径 PE。
3. TTM 利润口径 PE。
4. 最新季度扣非净利机械年化 PE。
5. 最新季度年化利润是否可持续。
6. 同业或行业估值中位数、范围或分位。
7. 估值变便宜是经营改善，还是利润分母临时放大。

`09` 必须评价利润分母质量；如果利润质量不足，`06` 不能无折扣使用该利润年化。

## 保存规则

正式 run 至少保存：

```text
run_manifest.json
run_context.json
source_registry.json
evidence_cache.jsonl
retrieval_log.jsonl
agents/*.md
agents/*.json
final_report.md
promotion_candidates.json
close_pack.md
```

如运行 11，还要保存：

```text
ui/compact.html
ui/full.html
ui/research_ui_manifest.json
ui/data.json
```

## 晋级规则

Agent 研究结果从 `runs/` 进入正式项目之前，必须同时满足：

1. 来源可追溯。
2. 口径已被 `07` 对账。
3. `08` 明确标注可晋级字段。
4. 数据缺口不会影响页面或数据库使用。
5. 用户确认，或后续代码显式读取对应字段。

未满足条件的内容只能留在 `runs/`，不能进入正式页面、数据库或模型训练材料。

## 历史研究规则

同一公司再次研究时，不能只重写一份新报告。必须先读最近一次 run，并比较：

1. 业务主线是否变化。
2. 收入结构是否变化。
3. 利润质量是否变化。
4. 估值分母是否变化。
5. 股价驱动是否变化。
6. 风险是否变化。

## 页面表达规则

`11` 只负责表达，不负责新增金融结论。

它只能使用：

1. `01` 最终签发的结论。
2. `07` 放行的事实和口径。
3. `08` 标注可晋级或可展示的字段。

页面产物不得把缺口画成确定数据，不得新增未被 Agent 支撑的判断。
