# Agent 研究产出升级方案

## 背景判断

振德医疗和粤桂股份两次研究暴露出一个问题：Agent 能把公司业务和基本财务讲出来，但离“能进入真实生产页面、支持后续复查和跨时间对比”还有差距。

主要缺口：

1. 估值不够深，只报当前 PE 不够，必须解释分母变化、历史估值和同业位置。
2. 研究产物结构化不足，Markdown 能读，但不能稳定进页面或数据库。
3. evidence/retrieval ledger 没被强制执行，后续无法审计和晋级。
4. 每个 Agent 的独立输出和最终报告没有进入正式研究库。
5. 缺少跨时间研究对比机制。

## 目标状态

每次正式单公司研究，至少产出四层结果：

1. `Agent 独立结论`：每个 Agent 的 Markdown + JSON。
2. `结构化事实和指标`：可进入候选字段表。
3. `最终研究结论`：final_report + promotion_candidates。
4. `页面产物`：compact.html + full.html + research_ui_manifest.json。

同时，所有结果都可以按 `symbol + as_of_date + run_id` 追溯。

## 对 10 个金融 Agent 的升级要求

### 03 财报与管理层信号 Agent

新增硬要求：

- 不只摘财报数字，要输出 `period_compare`：上一年、最新季度、TTM 或可得期间的变化。
- 必须区分收入变化来自价格、销量、结构、并表、汇率还是一次性因素。
- 必须输出管理层信号是否支持当前市场叙事。

### 04 轻量财务建模 Agent

新增硬要求：

- 输出 `earnings_bridge`：2025A -> TTM -> 最新季度年化 -> 三情景。
- 对最新季度年化必须给公式和使用限制。
- 明确哪些假设只是在“业务不变”下的 mechanically annualized，哪些是经营情景。

### 05 市场与行业研究 Agent

新增硬要求：

- 给行业位置，不只给行业描述。
- 给同业篮子，并说明为什么这些公司可比、哪些不可比。
- 如涉及商品/政策/地缘，必须给直接变量、间接变量和交易叙事的传导链。

### 06 估值与股价驱动核查 Agent

这是当前最需要升级的 Agent。新增硬要求：

- 当前市值、股价、总股本和估值基准日。
- 上年利润口径 PE。
- TTM 利润口径 PE。
- 最新季度扣非净利年化 PE，并明确这是“机械年化口径”，不能等同预测。
- 如果业务不变、最新季度利润延续，估值会怎样变化。
- 同业/行业估值中位数、范围和分位；无法取得时写缺口。
- 历史 PE 或历史市值/利润对照：至少比较上一年同期或上一个财报节点。
- 估值结论必须回答：变便宜是因为利润真的改善，还是因为只用了不可持续的季度利润分母。

### 07 事实一致性对账 Agent

新增硬要求：

- 检查所有 PE 分母口径。
- 检查同业可比性。
- 检查 HTML 页面不得把数据缺口画成确定图表。

### 08 研究收口与晋级 Agent

新增硬要求：

- 明确哪些 Agent 输出可入库，哪些只是 Markdown。
- 检查 `evidence_cache.jsonl`、`retrieval_log.jsonl` 是否足够支撑晋级。
- 检查 `11` 页面产物是否只展示了可支撑结论。

### 09 财务质量审查 Agent

新增硬要求：

- 对估值分母给质量评价：利润能不能用于估值。
- 如果最新季度利润强但 CFO 弱，必须提醒 06 不能无折扣年化。

### 10 实体、监管与舆情风险 Agent

新增硬要求：

- 给估值折价因素：监管、处罚、问询、重大项目、异常波动是否影响估值信任度。

## 新增 11 研究页面生成 Agent

`11` 只负责表达，不负责研究。它读取 `01/07/08` 后的结论，生成：

- `ui/compact.html`
- `ui/full.html`
- `ui/research_ui_manifest.json`
- `ui/data.json`

页面实现只嵌入这些产物，不重新解释金融结论。

## 数据保存要求

每个 Agent 都要有独立输出：

- `agents/<agent_id>.md`
- `agents/<agent_id>.json`

最终报告也要保存：

- `final_report.md`
- `promotion_candidates.json`
- `close_pack.md`

正式化后进入独立研究库：

- `company_research_runs`
- `company_research_agent_outputs`
- `company_research_facts`
- `company_research_valuation_snapshots`
- `company_research_ui_artifacts`
- `company_research_comparisons`

## 新旧研究对比

下一次研究同一公司时，不应从零开始，而是先读取最近一次研究：

| 对比维度 | 说明 |
|---|---|
| 业务主线是否变化 | 公司是否换了主要利润逻辑 |
| 收入结构是否变化 | 产品/地区/渠道占比变化 |
| 利润质量是否变化 | 扣非、CFO、存货、负债变化 |
| 估值分母是否变化 | 上年、TTM、最新季度年化利润变化 |
| 股价驱动是否变化 | 商品/主题/政策/业绩/资金主线变化 |
| 风险是否变化 | 监管、项目、舆情、财务风险变化 |

## 执行顺序建议

1. 先在文档层固化 11 Agent 和升级后的输出 schema。
2. 下一次公司研究时强制跑新版 04/06/07/08/11。
3. 先用文件系统保存完整产物。
4. 页面研究团队接入 `compact.html/full.html` 的静态嵌入。
5. 等页面形态稳定后，再实现 `company_research.db`。
