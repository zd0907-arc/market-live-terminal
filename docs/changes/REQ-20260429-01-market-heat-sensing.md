## 2. 一句话结论

本需求不是再做一个复杂资讯平台，而是给股票研究增加一个轻量的“市场温度计”：

```text
先用全市场行情、成交额、L2资金和板块成分聚合，判断当前市场正在炒什么、什么板块最持续；
再把这个市场热度作为 Codex 研究和选股解释的上层背景。
```

第一版只做脚本和 JSON/Markdown 输出，不先做页面、不全市场拉新闻、不做 LLM 自动研报。

## 3. 用户 Story

### Story 1：每天知道市场热什么

作为用户，盘后数据跑完后，我想问 Codex：

```text
今天市场最热的板块是什么？
哪些是新冒头，哪些是连续强？
哪些只是单日冲高，可能明天追高风险大？
```

Codex 应基于本地数据和少量稳定外部板块源，给出：

```text
今日最热板块 Top N
近 5 日持续最强板块 Top N
近 20 日主线板块 Top N
新冒头板块
退潮/过热板块
每个板块的代表股票
```

### Story 2：研究单票时知道它是不是在主线里

作为用户，当我研究一只候选票时，我想知道：

```text
这只票属于哪个热门板块？
它是板块龙头、容量核心、补涨，还是独立妖股？
板块热度是在上升、延续，还是退潮？
```

Codex 应能把个股结论放回板块背景，而不是只看个股技术面。

### Story 3：回看过去一年热点轮动

作为用户，我想研究过去一年市场热点变化：

```text
哪些板块多次进入热度 Top10？
哪些板块一日游，哪些能持续两三周？
板块热度启动后，龙头/补涨股后续收益如何？
板块退潮时，个股信号是否应该降权？
```

系统应能基于历史个股数据，重建板块热度历史，并支持策略回测。

### Story 4：最终需要一个简单可视化页面

作为用户，虽然主要通过 Codex 对话研究，但我仍需要一个简单页面理解：

```text
热点板块排名
热度曲线
板块内代表票走势
板块轮动时间线
```

页面只做理解辅助，不承载复杂研究逻辑。

## 4. 已调研数据源结论

### 4.1 可作为核心的数据源

#### 本地 atomic 行情/L2

可用内容：

```text
atomic_trade_daily
selection_feature_daily
```

用途：

```text
个股涨跌幅
成交额
L2 主力净流入
近 5/10/20 日强度
上涨/大涨/涨停分布
```

判断：核心数据源，稳定。

#### 同花顺行业汇总（AKShare 包装）

已实测：

```text
stock_board_industry_summary_ths
```

返回：

```text
90 个行业
涨跌幅
总成交量/成交额
净流入
上涨/下跌家数
领涨股
```

判断：行业层可用，适合作为第一版行业热度输入。

### 4.2 可辅助但不能强依赖

#### 东方财富板块排名/成分股

4/28 demo 使用：

```text
push2.eastmoney.com/api/qt/clist/get
push2delay.eastmoney.com/api/qt/clist/get
```

可用内容：

```text
行业/概念板块排名
板块成分股
当日涨幅、成交额、资金净流入
```

风险：

```text
无官方 SLA
会偶发 RemoteDisconnected / ProxyError
板块 K 线接口更不稳定
```

判断：可用于概念板块和成分股补充，但要有失败降级。

#### 同花顺概念名称/概念摘要

已实测：

```text
stock_board_concept_name_ths
stock_board_concept_summary_ths
```

问题：

```text
概念名称可拉但慢
概念历史指数不稳定，部分只到 2025-02-28
成分股接口在当前 AKShare 版本不完整
```

判断：可做概念候选发现，不能作为历史回测主数据。

### 4.3 不适合作为第一版核心

#### 全市场新闻/公告/财报

本地体检结果：

```text
stock_company_profiles：30 只
stock_financial_snapshots：30 只
stock_events 近期每日只覆盖十几到二十几只股票
```

判断：不能全市场使用。只允许在“Top 板块 + 代表票”阶段按需解释。

## 5. 板块定义

第一版分三类。

### 5.1 行业板块

来源：同花顺行业汇总。

用途：稳定观察市场行业轮动。

### 5.2 概念板块

来源：东方财富概念板块排名/成分股，失败时跳过。

用途：捕捉市场短期主题，如液冷、机器人、氦气、CPO。

### 5.3 自定义主题篮子

由项目维护 `theme -> symbols` 映射。

第一批建议：

```text
AI算力硬件
液冷/温控
人形机器人
创新药/CXO
船舶海工
半导体设备
存储芯片
PCB
煤炭能源
工业气体
低空经济
固态电池
军工信息化
```

用途：历史研究和回测的主力，因为成分股可控、可解释、可回填过去一年。

## 6. 热度定义

### 6.1 今日热度 hot_score

第一版公式：

```text
hot_score =
  30% 当日涨幅分位
+ 20% 成交额放大分位
+ 20% L2 主力净流入分位
+ 15% 上涨家数占比
+ 10% 大涨/涨停家数
+  5% 代表股强度
```

### 6.2 持续性 persistence_score

```text
persistence_score =
  35% 近5日累计涨幅
+ 25% 近10日强度
+ 20% 资金连续性
+ 15% 板块内上涨扩散度
+  5% 龙头稳定性
```

### 6.3 风险标签

```text
new_emerging       # 新冒头
mainline           # 主线延续
overheated         # 过热
fading             # 退潮
one_day_spike      # 单日脉冲
leader_only        # 龙头独涨，板块未扩散
```

## 11. 明确边界

第一版不做：

```text
不全市场新闻抓取
不全市场财报总结
不做自动投资建议
不替代选股策略
不做复杂页面
不依赖单一免费外部接口
```

## 12. 验收标准

- 能在本地命令行一键输出当天市场热度报告。
- 外部概念接口失败时，脚本仍能基于本地数据和行业源输出结果。
- 报告中每个板块必须有可解释的量化指标和代表票。
- 能保存 JSON，便于后续页面和历史回测复用。
- 不引入长耗时全市场新闻/公告任务。
