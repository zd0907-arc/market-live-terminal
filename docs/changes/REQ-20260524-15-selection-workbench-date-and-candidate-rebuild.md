# REQ-20260524-15-selection-workbench-date-and-candidate-rebuild

## 2. 背景与目标
选股工作台当前默认读取每日综合候选池。底层 `selection_feature_daily / selection_signal_daily` 已覆盖 `2024-09-02 ~ 2026-05-22`，但统一候选池只覆盖最近部分日期。页面一次性请求全历史日期时还会命中后端 540 天返回上限，导致最近日期清单缺失，左右切换可能从 5 月跳回 2/3 月。

目标：
- 日期切换以最近可用研究窗口为主，不因全历史范围截断跳到旧日期。
- 选择一个有评分底座但没有候选池结果的交易日时，按钮应能触发该日候选生成并展示结果。
- 保持统一候选池作为页面入口，不回退到旧单策略调试页。

## 3. 方案与边界
- 做什么：
  - 调整后端每日日期接口，明确返回可查询/有候选状态，并避免大范围请求只返回旧窗口。
  - 调整前端日期初始化与左右切换，优先围绕最近窗口工作。
  - 调整“查看候选”流程：目标日期无候选但有评分底座时先运行 `daily-refresh`，再加载候选。
- 不做什么：
  - 不重写策略算法。
  - 不把 `2024-09-02` 至今全量候选一次性全部补满。
  - 不把选股结果描述为稳定自动买入信号。

## 4. 执行步骤（按顺序）
1. 复核现有文档、前后端代码和数据库覆盖。
2. 修复日期接口和前端日期交互。
3. 运行最近窗口候选回填 smoke。
4. 验证页面与接口行为。

## 5. 验收标准（Given/When/Then，绝对时间）
- Given `2026-05-24` 本地研究站读取 `/Users/dong/Desktop/AIGC/market-data/selection/selection_research.db`
- When 打开 `/selection-research`
- Then 默认日期应落在最新可用交易日附近，不跳到 `2026-02` 或 `2026-03`
- When 选择 `2026-05-19` 这类有底层评分但无候选结果的交易日并点击按钮
- Then 系统应尝试生成该日候选，再展示结果或给出明确失败信息

## 6. 风险与回滚
- 风险：`daily-refresh` 是写接口，若本地未配置写权限，前端无法自动生成候选。
- 风险：当前两个规则策略仍读 4 月实验 CSV，5 月只可能主要生成星火模型候选。
- 回滚：回退本卡涉及的前端页面、后端每日候选日期接口和相关类型定义。

## 7. 结果回填
- 实际改动：
  - 后端 `/api/selection/daily-trade-dates` 大范围查询改为保留最近 540 天窗口，返回 `truncated/window_days` 以及候选、评分、运行状态元数据。
  - 前端日期选择只允许选择后端明确可选的日期；绿点表示已有候选，黄点表示有评分底座可运行。
  - 前端“查看候选”和左右切换会在需要时先尝试运行当日候选；已跑完但 0 条结果时，候选菜单显示“已跑完，今天没有可推荐的股票。”。
- 验证结果：
  - `python3 -m pytest backend/tests/test_selection_daily_workbench.py`：5 passed。
  - `npm run build`：通过。
  - 隔离后端 `8011` 实测：底层评分覆盖 `2024-09-02 ~ 2026-05-22`；候选池覆盖 `2026-03-02 ~ 2026-05-22` 共 53 个日期；全历史日期接口返回最近窗口 `2024-11-28 ~ 2026-05-22`，不再截断到 2026-02。
  - 隔离前端 `3012` 实测：默认进入 `2026-05-22` 并显示 3 条候选；选择 `2026-05-19` 显示“已跑完，今天没有可推荐的股票。”。
- 遗留问题：
  - 当前两个规则策略仍依赖 4 月实验产物，5 月候选主要来自 `spark_opportunity_selector`，这次未重写策略数据源。
