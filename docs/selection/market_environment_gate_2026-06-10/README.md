## 先给结论

这个方向值得单独成线。它不是再做一个新的选股模型，而是在每日候选已经产出之后，增加一层“市场环境水位判断”，回答当天到底适不适合参与、哪些来源只能观察、哪些情况下应暂停新开仓。

训练范围不一致的问题必须拆开看：

- 如果要横向比较四个来源“谁更强”，必须做训练截止点和样本范围对齐，否则不公平。
- 如果验证的是“面对当时系统已经给出的推荐，用当天市场环境做二次过滤能不能改善实战结果”，则可以基于历史候选快照继续研究。这个问题的核心不是模型训练是否一致，而是市场环境指标是否点时安全、是否只使用信号日当时已经可见的数据。

正式研究不应只看 2026 年。2026 年 3 月到 6 月只是当前四个统一候选来源的近期实盘快照样本，适合解释最近体感；市场环境水位本身应从本地可用的 2024-09-02 长样本开始计算，用来覆盖更多顺风、震荡、逆风阶段。

## 研究目标

1. 每天生成一个市场环境水位：攻击、谨慎、防守，必要时再细分为小盘冰点、普跌修复、指数强但个股弱、情绪退潮等业务状态。
2. 验证市场环境与四个候选来源后续表现之间有没有稳定关系。
3. 验证市场环境门控是否能提高实战可用性：少踩坑、少占用资金、少在弱市硬拿半个月。
4. 最终在选股工作台中展示市场环境、候选票可参与程度和可视化水位图。

## 防守优先原则

市场环境进入防守状态时，默认结论应是“暂停新开仓”。只有在数据证明某类信号能穿越弱市时，才允许出现例外。

例外规则必须满足：

- 在防守环境下单独验证，不能拿顺风环境表现混在一起证明。
- 分来源验证，不能用四个来源合并样本证明某一个来源有效。
- 同时改善亏损指标和机会指标，不能只看最大冲高。
- 至少跨月份稳定，不能只靠某一个月或少数样本成立。
- 必须报告覆盖率和误杀率。

星火机会模型需要额外做分数分层验证：

| 分层 | 业务假设 |
|---|---|
| 35 分左右 | 普通候选，不应天然获得弱市参与资格 |
| 40 分以上 | 可能是高置信候选，但必须证明弱市也能降低亏损或明显提高冲高质量 |

如果 40 分以上样本无法在防守环境中证明优势，则防守环境仍按暂停新开仓处理。

## 来源验证重点

四个来源不设业务优先级，验收只看不同市场水位下的真实效果。

| 来源 | 重点验证问题 |
|---|---|
| 星火机会模型 | 最近失效是市场逆风导致，还是模型本身在弱市无法识别风险；重点看 35 分左右和 40 分以上在防守环境下是否有显著差异 |
| 试盘识别 | 是否能提前识别小票资金动作，同时在弱市少误导；重点看当日观察到三日确认的转化质量 |
| 资金流回调稳健策略 | 是否只在市场修复或顺风时有效，防守环境下是否应完全暂停 |
| 趋势延续策略 | 是否具备低频高价值特征；无候选时到底是在有效避险，还是接入口径漏掉了观察池 |

## 数据使用原则

本研究分成两层数据，不能混用：

| 层级 | 使用范围 | 解决的问题 | 备注 |
|---|---|---|---|
| 市场环境长样本 | 从 2024-09-02 起 | 市场水位指标是否稳定、不同市场阶段怎么定义 | 应尽量用足全部日线事实数据 |
| 已发候选门控验证 | 按各来源真实候选快照起点 | 当系统当天已经给出推荐时，市场环境能不能辅助决定买不买 | 不能伪造过去没有产出的候选 |
| 固定版本回放验证 | 需要单独实验 | 如果把某个模型/策略固定在某个版本，回放到更早月份会怎样 | 必须点时安全，不能用未来训练结果 |

因此，2024-09 之后的数据必须用于市场环境分层和阈值稳定性研究；但四个当前候选来源如果在统一候选池里只从 2026 年开始有快照，就只能从真实快照起点做“已发推荐门控验证”。如果要把候选验证也扩展到 2024-09，需要另做“固定版本回放”，并明确这不等同于当时真实日跑推荐。

本研究只解决“当天要不要参与、参与哪类来源”的问题，不替代原有四个候选来源。

当前纳入评估的来源：

| 来源 | 当前定位 | 主要目标 |
|---|---|---|
| 星火模型 | 机会模型 | 判断未来约 22 个交易日有没有较大冲高概率 |
| 资金流回调稳健策略 | 规则策略 | 找资金趋势仍在、回调后可能修复的票 |
| 趋势延续策略 | 规则策略 | 找已经走强后可能二波延续的票 |
| 试盘识别 | 观察/确认策略 | 识别资金试盘后是否可能继续进入 |

不在本阶段做的事：

- 不重新训练四个来源。
- 不直接改每日候选池排序。
- 不把相关性结论直接升级成自动买入规则。
- 不把未跑满周期的候选当成完整 22 日结论。

## 公平性口径

### 1. 模型/策略本身横评

这是“谁选股能力更强”的问题。这个问题必须尽量拉齐：

- 统一信号日范围，例如都只比较 2026-03-01 之后已经真实产出的候选。
- 统一结果周期，例如次日开盘买入后 5 日、10 日、22 日最大冲高和收盘收益。
- 区分完整周期和未完整周期，未跑满 22 日只能标记为观察到当前。
- 模型类必须使用训练截止日之后的样本，不能拿训练期内信号证明模型泛化能力。
- 规则策略要固定规则版本，不能用后来的规则解释过去的信号。

在训练范围不一致时，不能下这些结论：

- 不能直接说某个来源绝对强于另一个来源。
- 不能把星火训练期内的表现当成独立实盘表现。
- 不能用趋势延续策略最近无候选直接证明策略无效，只能证明当前正式入口在该市场环境下没有给出可买票，或者接入方式需要复核。

### 2. 市场环境覆盖层验证

这是“系统已经给了推荐后，要不要参与”的问题。它可以基于历史每日推荐继续做，因为它评估的是二次决策层。

公平做法是：

- 对每个来源分别比较“不过滤”和“按市场环境过滤”的差异。
- 主要看过滤带来的提升，而不是只比较来源之间的绝对收益。
- 合并样本只能作为辅助结论，必须说明各来源样本权重，避免星火样本量吞掉其他来源。
- 市场指标必须只使用信号日收盘前已经可见的数据。
- 同一股票短期重复信号要去重或单独标记，避免把一次行情膨胀成多条独立样本。
- 同一套市场门控阈值不能在 5 月、6 月样本上反复调到最好后再宣称有效。

换句话说，候选来源训练范围不一致会影响“来源横评”的公平性，但不必然破坏“市场环境是否能改善已产出推荐”的验证。后者的关键是点时安全和样本外验证。

## 执行规范：主 Agent + 子 Agent

后续执行必须遵循 `docs/strategy-rework/agent-workflow.md` 的主 Agent + 子 Agent 工作流。

### 主 Agent 职责

主 Agent 只负责：

- 和用户确认业务目标。
- 拆分研究假设。
- 定义数据口径和验收标准。
- 派发子 Agent。
- 审阅子 Agent 结果。
- 决定哪些结论进入正式计划或产品。

主 Agent 不应一个人同时完成规划、跑数、写脚本、整理报告和产品决策。

### 子 Agent 任务拆分

每个子 Agent 只能拿一个清晰任务：

| 子 Agent | 任务 | 输出 |
|---|---|---|
| 数据覆盖 Agent | 核查 2024-09 起各库覆盖和缺口 | 数据范围表、缺口清单 |
| 市场水位 Agent | 生成 2024-09 起每日市场环境宽表 | `market_state_daily`、字段说明 |
| 候选结果 Agent | 计算各来源候选 5/10/22 日结果 | 候选结果明细、分来源汇总 |
| 门控验证 Agent | 比较不过滤、软门控、硬门控 | 分层报告、覆盖率、误杀率 |
| 可视化 Agent | 设计市场水位图表和页面信息层级 | 图表方案、页面字段草案 |
| 评审 Agent | 检查泄漏、样本偏差和结论等级 | 风险清单、采纳建议 |

派发子 Agent 时必须写清楚：

- 业务背景。
- 本次只验证什么。
- 输入数据路径和日期范围。
- 允许新增哪些文件。
- 禁止覆盖旧实验、禁止改前端、禁止发明新入口。
- 输出必须包含 README、summary、结果表和简短结论。
- 是否建议采纳，以及采纳到什么等级：观察性发现、继续跟踪、试运行、暂不采纳。

子 Agent 输出固定格式：

```text
做了什么
样本范围
关键数字
业务结论
主要风险
是否建议采纳
下一步建议
```

冲突处理：

- 不同子 Agent 结果冲突时，不取平均、不拼装第三套规则。
- 主 Agent 必须按同一验收口径复核，必要时追加验证或暂停采纳。
- 任何阈值、来源定义、产品结论的变更，都必须由主 Agent 汇总后进入文档，不由子 Agent 自行决定。

## 市场环境指标

### 核心指标

优先从“个股真实水位”出发，而不是只看指数：

- 全市场上涨占比：最近 1、3、5、10、20 个交易日收益为正的股票比例。
- 全市场中位涨跌幅：最近 1、3、5、10、20 个交易日股票收益的中位数。
- 小盘上涨占比与中位涨跌幅：反映短线生态是否适合题材和小票。
- 大盘上涨占比与中位涨跌幅：判断是否只是权重托指数。
- 小盘相对大盘强弱：识别指数好看但个股难做的环境。

### 指数辅助

指数不替代个股水位，只作为外部参照：

- 中证 1000：小盘环境。
- 中证 500：中小盘环境。
- 沪深 300：权重环境。
- 上证指数：主指数环境。
- 创业板指：成长和 20cm 风险偏好。

### 周期分层

不同周期回答不同问题：

| 周期 | 业务含义 | 用途 |
|---|---|---|
| 1 日 | 当天情绪冲击 | 判断是否刚出现急跌或修复 |
| 3 日 | 短线情绪 | 对次日参与最敏感 |
| 5 日 | 操作水位 | 作为门控主周期候选 |
| 10 日 | 小趋势 | 判断弱势是否已经持续 |
| 20 日 | 月度环境 | 判断大背景是顺风还是逆风 |

研究阶段不预设唯一周期，需要同时验证 1、3、5、10、20 日，再决定哪几个用于产品展示和门控。

## 验证方法

### 1. 构建每日市场状态

每个交易日生成一条市场环境记录：

- 全市场水位。
- 小盘水位。
- 大盘水位。
- 指数辅助状态。
- 综合市场等级。
- 触发该等级的前三个原因。

所有字段只允许使用该交易日及之前的数据。

### 2. 关联候选来源表现

把每日市场状态关联到当日候选：

```text
trade_date + source_id + symbol -> signal_date_market_state -> future_outcome
```

结果周期：

- 次日开盘买入后 5 日最大冲高。
- 次日开盘买入后 10 日最大冲高。
- 次日开盘买入后 22 日最大冲高。
- 观察期收盘收益。
- 最大回撤。
- 是否达到 5%、10%、15%、20% 冲高。
- 是否触发假设止损。

未跑满周期的样本单独打标：

- `full_22d`
- `partial_to_today`

### 3. 关联性验证

先证明市场水位和候选表现是否有关：

- 按上涨占比、中位涨跌幅做高、中、低分层。
- 计算每层的平均冲高、命中率、收盘收益、回撤。
- 对每日来源表现和市场水位做 Spearman 相关，优先看排序关系。
- 每个来源单独看，避免被星火样本量吞掉其他来源。

### 4. 验收指标优先级

本研究的第一目标是少亏、少踩坑，所以主指标优先看风险，不先看平均收益。

主验收指标：

- 最大回撤是否下降。
- 负收益候选比例是否下降。
- 假设止损触发率是否下降。
- 资金占用天数是否下降。
- 连续踩坑天数是否下降。
- 防守期新开仓建议是否明显减少。

次级指标：

- 平均冲高是否提升。
- 10%、15%、20% 冲高命中率是否提升。
- 被拦截后错过的大机会有多少。
- 强市是否被过度误杀。

只有在主验收指标改善的前提下，收益和冲高改善才有采纳意义。

### 5. 门控回测

比较三组结果：

| 组别 | 含义 |
|---|---|
| 基线 | 所有候选都按原逻辑参与 |
| 提示门控 | 候选仍展示，但标记为观察或不建议买 |
| 暂停门控 | 防守环境默认暂停新开仓，只有被证明有效的例外才允许参与 |

核心看：

- 最大回撤是否下降。
- 负收益候选比例是否下降。
- 假设止损触发率是否下降。
- 资金占用天数是否下降。
- 门控覆盖率是多少，也就是每天还有多少票可参与。
- 误杀率是多少，也就是被拦截后仍然走出大冲高的比例。
- 强市是否过度拦截。
- 放弃候选后是否错过大机会。
- 命中率、平均冲高和收盘收益是否改善。

### 6. 高置信例外验证

高置信例外必须预注册验证口径，不能事后挑一个最好看的阈值。

优先验证：

- 星火机会模型：35 分以下、35 到 40 分、40 分以上。
- 每个来源的排名分层：Top 1、Top 3、Top 5 或来源内分位。
- 试盘识别：当日观察和三日确认分开验证。
- 趋势延续策略：低频信号单独验证，不并入高频来源。

采纳条件：

- 在防守环境下，亏损类主指标明显改善。
- 样本外月份仍然成立。
- 覆盖率不能低到只剩孤例。
- 误杀强票的代价可解释、可接受。

如果达不到这些条件，防守环境下不设高置信例外。

### 7. 样本外验证

阈值选择必须用前段样本，后段样本只验证：

- 例如用 2026-03 到 2026-04 选阈值，再看 2026-05 到 2026-06。
- 如果未来补齐更长历史，再做滚动月度验证。
- 分位阈值要用训练段或滚动历史计算，不能用全样本未来数据反推。
- 不允许只用 5 月、6 月调参后再证明 5 月、6 月有效。

## 初步观察

以下只是研究起点，不是最终交易规则。

按当前本地数据，2026 年月度个股水位大致呈现：

| 月份 | 全市场中位涨跌幅 | 上涨占比 | 业务判断 |
|---|---:|---:|---|
| 2026-01 | 约 +3.1% | 约 66.6% | 顺风 |
| 2026-02 | 约 +4.4% | 约 81.1% | 强顺风 |
| 2026-03 | 约 -8.0% | 约 18.3% | 普跌逆风 |
| 2026-04 | 约 +0.8% | 约 53.1% | 修复震荡 |
| 2026-05 | 约 -8.6% | 约 22.4% | 逆风 |
| 2026-06 截至 06-10 | 约 -7.0% | 约 17.3% | 强逆风 |

初步分层显示，短周期市场水位对候选后续表现有明显解释力。例如在买入型候选中，`3 日全市场上涨占比`高分层相比低分层，平均冲高、10% 冲高命中率和收盘收益都更好。

截至 2026-06-10，本地数据给出的环境更接近防守状态：

- 5 日全市场中位涨跌幅约 -4.4%。
- 5 日全市场上涨占比约 19%。
- 20 日小盘上涨占比约 7.5%。
- 中证 1000 近 5 日、10 日仍为负。

这说明当前不是“模型突然完全失效”一个解释，更可能是候选来源遇到了明显逆风市场。防守环境下默认暂停新开仓；是否存在可穿越弱市的例外，需要用后续门控回测确认。

## 产品落地设想

### 选股工作台顶部

每天展示一个市场环境卡片：

- 今日水位：攻击、谨慎、防守。
- 水位分数：0 到 100。
- 主要原因：最多三条业务语言。
- 默认动作：可参与、观察为主、暂停新开仓。
- 被拦截来源：说明哪些来源今天不建议买。
- 可观察候选：防守环境下仍展示候选，但不暗示可以买。

示例：

```text
今日市场环境：防守
原因：5 日上涨占比 19%，小盘 20 日上涨占比 7.5%，中证 1000 仍在 10 日弱势区。
建议：暂停新开仓；星火机会模型单独信号不参与；试盘识别只观察；资金流回调稳健策略和趋势延续策略没有被证明能穿越该环境时不买。
```

### 候选票标记

每只候选增加市场环境解释：

- 环境允许：市场水位支持该来源。
- 环境观察：候选可以继续跟踪，但不建议新开仓。
- 环境阻断：市场环境与来源特征冲突，建议暂停买入。

候选解释不只写“红灯/绿灯”，必须写清楚原因：

```text
环境观察：小盘 5 日上涨占比低于 30%，该票来自 22 日冲高模型，当前更适合等待环境修复。
```

防守环境下，页面按钮和标签不能暗示“建议买”。推荐文案应使用：

- `暂停新开仓`
- `只观察`
- `等待环境修复`
- `需数据证明后才允许例外`

## 复盘解释要求

复盘页需要解释门控有没有帮忙，而不是只解释模型有没有选中。

必须展示：

- 哪些候选因市场环境被拦截。
- 拦截后这些候选实际表现如何。
- 是否错过大机会。
- 错过机会是否在可接受范围内。
- 防守期踩坑率是否下降。

这些复盘用于校准门控，不用于追责用户的人工决策。当前阶段不记录真实买卖操作，也不做真实账户收益归因。

## 可视化方案

可视化目标不是展示更多数字，而是让人一眼看到“水位在升还是在降”。

### 1. 市场水位折线图

展示综合水位分数，背景用攻击、谨慎、防守三段色带。
作用：一眼看当前处于什么区间，最近是否从冰点修复。

### 2. 上涨占比柱状图

展示 1、3、5、10、20 日上涨占比。
作用：看短线是否只是一天反弹，还是多个周期都在改善。

### 3. 中位涨跌幅折线图

展示全市场、小盘、大盘三条线。
作用：识别“指数没跌但个股很难做”的环境。

### 4. 指数对照图

展示中证 1000、中证 500、沪深 300、创业板指的短周期表现。
作用：辅助判断资金偏好是小盘、权重还是成长。

### 5. 来源表现分层图

按市场水位展示四个来源的命中率、平均冲高和收盘收益。
作用：回答“什么环境下该信哪个来源”。

## 阶段计划

### P0：研究口径固化

交付物：

- 本研究计划。
- 数据口径清单。
- 公平性说明。
- 初步指标列表。

验收标准：

- 能明确区分来源横评和市场覆盖层验证。
- 能解释为什么训练范围不一致不应直接横评，但可以验证二次门控。

### P1：离线验证

交付物：

- 每日市场环境宽表。
- 候选来源与市场环境关联明细。
- 月度、来源、市场水位三维验证报告。
- 阈值敏感性报告。

验收标准：

- 每个交易日都能复现当时市场水位。
- 每个来源都能看到不过滤和过滤后的差异。
- 至少覆盖完整月度对比，不能只看最近几天。
- 报告优先给出踩坑下降、回撤下降、覆盖率、误杀机会和置信度，不只报最好看的收益指标。

### P2：门控规则试运行

交付物：

- 软门控规则。
- 硬门控候选规则。
- 放弃候选机会损失统计。

验收标准：

- 弱市下回撤和资金占用有改善。
- 强市下不会明显错过大部分高冲高机会。
- 每条规则都有业务解释，不只是黑箱分数。

### P3：工作台展示

交付物：

- 市场环境卡片。
- 候选票环境标记。
- 市场水位图表。
- 来源适配建议。

验收标准：

- 用户进入选股页能先看到当天环境。
- 每个候选能说明“为什么现在能买或不适合买”。
- 图表能直观看出市场水位变化。

## 风险与待解决问题

1. 独立指数缓存当前较短，但 `model_feature_store.db` 内嵌指数已覆盖长样本；后续脚本必须选对指数来源，避免误以为只能做近期验证。
2. 小盘/大盘分层如果使用当前市值，会引入历史偏差，正式验证应尽量换成点时口径。
3. 趋势延续策略最近无候选，需要单独复核是策略真的严格，还是观察池没有进入统一候选池。
4. 试盘 D3 样本少，不能过早下稳定结论。
5. 市场环境和候选表现即使相关，也不等于因果；最终只能作为门控和实盘决策辅助，不直接生成仓位。
6. 过度门控可能错过逆势强票，因此必须统计“拦截后错过的大机会”。
7. 多指标、多周期同时试验容易偶然有效，必须留出样本或后续滚动验证。
