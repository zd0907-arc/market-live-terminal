# 市场温度雷达调研评估与需求定义

更新时间：2026-06-18

关联产品定义：`docs/selection/market_temperature_product_definition.md`。本文件负责记录数据口径、接口和落地缺口；产品定义文件负责记录页面目标、用户判断方式和信息架构。

## 结论

“市场温度、赛道强度、资金迁移、主题生命周期”这个方向可以落地，而且第一版不需要新增外部数据源：现有的市场水位、细颗粒热点、粗颗粒可交易主题、L2 盘后数据已经能支撑一个盘后研究页。

但要注意两条边界：

1. 当前可直接上线的是“盘后市场感知页”，用于看今天和最近一段时间市场在交易什么。
2. 用户最想要的“上半年到底是谁在走主线、资金从哪里迁到哪里”需要新增后端聚合层，不能只靠前端把热点页数据拼一拼。

## 目标

这个页面不解决单只股票买卖点，而是回答四个问题：

1. 今天市场能不能参与：市场温度。
2. 当前强赛道在哪里：粗赛道和细赛道强度。
3. 交易重心往哪里走：升温、回流、新热、退潮的对照。
4. 一个主题处在什么阶段：启动、扩散、高潮、退潮。

成功标准：

- 用户不用看 600 个板块列表，也能快速知道当前主线和退潮方向。
- 每个分数旁边必须有支撑数据，不能只给抽象数字。
- 既能看当天，也能看最近 1 个月、3 个月、半年。
- 粗赛道可以下钻到细赛道，细赛道可以继续到成分股。
- 页面口径和现有“市场热点”页一致，不另起一套主题真源。

## 产品定义

### 1. 市场温度

展示形式：

- 一个 0 到 100 的温度值。
- 最近 N 日曲线。
- 旁边列出支撑数据，而不是只给一个分数。

第一版口径：

- 复用 `GET /api/selection/market-environment` 的 `water_score`。
- 同屏展示 5 日上涨占比、5 日中位涨跌、小盘上涨占比、中证 1000 5 日涨跌、热点 Top5 均分。

正式版口径：

建议新增 `temperature_score_v1`，来源为 `model_market_state_daily_v1`，分成明确可解释的贡献项：

| 模块 | 字段例子 | 回答的问题 |
|---|---|---|
| 成交热度 | 成交额、20 日量比 | 市场有没有量 |
| 市场广度 | 上涨占比、中位涨跌 | 是普涨还是少数抱团 |
| 情绪强度 | 涨停、跌停、炸板比例 | 情绪是进攻还是脆弱 |
| 指数位置 | 中证1000/500/沪深300/上证/创业板 | 大盘和小盘谁更强 |
| 热点共振 | Top5热点均分、Top10成交占比、L2净流入 | 热点是不是被资金集中交易 |

注意：当前没有 A50 字段。第一版先用沪深300、中证1000、中证500、上证、创业板替代。若必须加入 A50，需要后续从免费公开接口补，不作为当前首版依赖。

### 2. 赛道强度

展示形式：

- 粗赛道表格或矩阵，默认显示 18 个可交易主题。
- 每个粗赛道展示细分数、平均热度、平均排名、前排细分主题。
- 点击粗赛道后下钻到细赛道曲线和成分股。

第一版口径：

- 前端临时把 `fine_dashboard` 的细颗粒主题聚合成粗方向，用于验证页面表达。

正式版口径：

- 后端必须用 `tradable_theme_map.db` 输出稳定粗赛道聚合。
- 不建议长期用前端关键词聚合，因为会造成口径漂移。

### 3. 资金迁移

这里更准确的命名应是“交易重心迁移”，不能直接承诺是真实资金跨赛道搬家。

展示形式：

- 左侧：正在增强，包括主线再加速、持续升温、首次新热。
- 右侧：退潮观察。
- 中间或顶部给出迁移摘要，例如“电子材料继续前排，AI应用退潮观察”。

可用证据：

- 排名变化：rank_delta、rank_improve_5d。
- 热度变化：hot_change_5d。
- 近 5/20 日 Top30 命中次数。
- 成交占比和 L2 净流入。
- 新热、持续、退潮主题数量。

正式版需要新增：

- 粗赛道级别的日度成交占比曲线。
- 粗赛道级别的 L2 净流入曲线。
- 粗赛道之间的 TopN 排名迁移表。

### 4. 主题生命周期

现有市场热点页已经有可用的生命周期池：

| 阶段 | 现有口径 |
|---|---|
| 当日高潮 | 今日最强 Top5 |
| 启动 | 首次新热 |
| 回流/再加速 | 主线再加速 |
| 扩散/升温 | 持续升温 |
| 主线维持 | 持续主线 |
| 退潮 | 退潮观察 |

展示形式：

- 主题排名曲线或 rank bars。
- 标注启动、再加速、持续、退潮点。
- 同时支持粗主题和细主题。

正式版需要：

- 不能只取 `fine_dashboard` 返回的近 30 个点；需要后端输出 120 日或 260 日主题历史序列。
- 粗主题生命周期由细主题聚合而来，但要保留“前排细分是什么”，避免粗主题过于抽象。

## 缺口与风险

1. `water_score` 当前是选股门控水位，不是纯市场温度。它可以作为首版替代，但正式版应拆成独立的 `temperature_score_v1`。
2. A50 当前没有本地字段。若必须展示，需要单独接免费公开接口；当前首版不依赖。
3. `fine_dashboard` 更适合看当前热点 6 池，不适合直接生成半年主线曲线。半年主线需要读 v2 长表或新增聚合缓存。
4. 粗主题映射不能长期放前端关键词里，正式版要由后端基于 `tradable_theme_map.db` 输出。
5. “资金迁移”应先用“交易重心迁移”表达，证据是成交占比、L2、排名和生命周期迁移，不应夸大成真实资金账户级流向。
6. 免费外部接口只能补缺口，不应替代本地正式数据链路。当前优先补 A50，其他市场温度指标本地已有。

接口应读取：

### P2：做长期主线识别

在 P1 基础上输出：

- 最近 20/60/120 日主线排行。
- 粗主题强度曲线。
- 粗主题内部细分扩散路径。
- 从“新热”到“持续主线”再到“退潮”的阶段标注。
- 半年主线复盘：哪些主题是真主线，哪些只是单日热点。

### P3：补外部免费数据

仅在本地数据缺失时补：

- A50 指数。
- 可能的港股、海外算力链参考指数。

这部分必须单独验证接口稳定性，不纳入首版硬依赖。
