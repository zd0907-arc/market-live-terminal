# 机会发现模型最终说明书

更新时间：2026-05-16

## 结论

本轮沉淀下来的不是一个单一策略，而是一套“盘后选股 + 盘后持仓管理”的模型链路。

最终保留两个核心模型：

1. **星火机会模型**
   - 英文 ID：`spark_opportunity_selector`
   - 作用：每天盘后从全市场选出次日可关注/可买的机会票。
   - 对应产物：`opportunity_discovery_trade_l2_v0_1/model.joblib`

2. **守势持仓模型**
   - 英文 ID：`sentinel_postclose_exit`
   - 作用：每天盘后判断已经持有的票，次日开盘是继续持有还是卖出。
   - 对应产物：`postclose_exit_v0_2/models/*_postclose_exit.joblib` 与 `*_postclose_continuation.joblib`

推荐保留两种执行组合：

1. **星火进攻版**
   - 英文 ID：`spark_aggressive`
   - 买入：星火机会模型 top1 + 条件 top2
   - 卖出：守势持仓模型 `pc_model_th6_stop12`
   - 定位：收益优先，允许更多交易和更高卖飞率。

2. **星火稳健版**
   - 英文 ID：`spark_guarded`
   - 买入：星火机会模型 top1
   - 卖出：守势持仓模型 + 强势续拿门控 `pc_model_th6_guard12_stop12`
   - 定位：少卖飞、少交易，但收益更依赖少数大票。

## 1. 这套模型解决什么问题

你的目标不是让模型做完整自动交易，而是把模型接进每天晚上的选股工作流：

1. 盘后更新数据。
2. 模型输出明天优先关注/可买股票。
3. 老策略、热点板块、趋势主题也继续输出候选。
4. 你在工作台里看到多个来源的候选，做交叉验证。
5. 如果已经买入，持仓模型每天晚上给出次日开盘的处理建议。

所以这套模型分成两层：

| 层 | 模型 | 回答的问题 | 动作时间 |
|---|---|---|---|
| 买入层 | 星火机会模型 | 明天优先看哪只/哪几只票 | 今日盘后生成，次日开盘参考 |
| 持仓层 | 守势持仓模型 | 已持仓明天开盘卖不卖 | 今日盘后判断，次日开盘执行 |

## 2. 星火机会模型

### 2.1 名字

正式中文名：**星火机会模型**

记忆方式：它不是找“稳健价值股”，而是找未来一段时间可能点火、冲高的短线机会。

### 2.2 它在预测什么

它的核心目标是：

> 如果今天盘后给出信号，明天按真实开盘价买入，那么未来 22 个交易日内，这只股票有没有较高的冲高空间。

训练标签不是“最后一天收盘赚不赚钱”，而是重点看：

- 未来 22 个交易日最高涨幅。
- 是否达到 10%、15%、20%。
- 达到高点前经历过多大回撤。
- 次日是否高开太多、是否涨停买不到。

这就是为什么它叫“机会发现”，不是“买卖点完整交易策略”。

### 2.3 它用哪些信息

主要使用盘后可见数据：

- 日线价格和涨跌幅。
- 3/5/10/20 日涨幅。
- 波动率、均线距离、区间位置。
- L1/L2 主力净流入、超大单净流入。
- 5/10/20 日资金流持续性。
- 5 分钟 L2 聚合后的主动买入强度、最后 30 分钟资金。
- 热点主题排名、热度、是否高潮/衰退。
- 市场整体涨跌家数、市场中位涨幅、市场主力净流。
- 涨停、炸板、一字板、过热、出货风险等状态。

从 2026-03 以后，挂单/撤单/OIB/CVD 等数据开始更完整，但当前保留版主要仍按较长样本可用的 L2 交易特征训练，避免只吃 3 月以后短样本。

### 2.4 怎么解释它给出的票

不要把它理解成“模型知道这个股票为什么会涨”。更准确的解释是：

> 这只票在当前价格位置、资金行为、主题热度和市场状态的组合上，像历史上未来 22 个交易日内出现过明显冲高的样本。

工作台里建议给每个模型候选显示这些解释字段：

- `model_name`：星火机会模型
- `model_id`：`spark_opportunity_selector`
- `signal_type`：22 日冲高机会
- `rank`：模型排序
- `score`：机会分
- `expected_horizon`：22 个交易日
- `buy_rule`：次日开盘高开不超过 6.8%，且不接近涨停才考虑
- `risk_tags`：高开过大、涨停接力、主题高潮、20 日涨幅过热、出货风险
- `explain_factors`：资金强、突破强、热点强、位置合适、市场环境支持等

如果未来有 3 个不同选股模型，每个模型都必须输出类似字段。这样你不是只看“谁排第一”，而是看：

- 这个模型看的是 3-5 天机会，还是 22 天冲高机会。
- 它偏资金回流、趋势突破、热点龙头，还是事件驱动。
- 它当前是否和热点主题、老策略、人工观察一致。

### 2.5 当前验证结果

滚动月度验证：

| 验证月 | top1 达到 15% | top1 平均最大冲高 | 简化持仓最佳收益 |
|---|---:|---:|---:|
| 2026-01 | 40.00% | 14.85% | +1.10% |
| 2026-02 | 40.00% | 17.29% | +24.43% |
| 2026-03 | 63.64% | 36.25% | +89.79% |
| 2026-04 部分 | 100.00% | 20.58% | +18.22% |

解释：

- 选股信号有价值，不是纯随机。
- 3 月贡献很大，不能把单月收益当长期稳定水平。
- 单靠固定止盈/止损不能充分拿住收益，所以需要持仓模型。

## 3. 守势持仓模型

### 3.1 名字

正式中文名：**守势持仓模型**

记忆方式：它不是盘中盯盘，也不是自动高频卖点；它每天晚上守住已有仓位，判断第二天要不要撤。

### 3.2 它在预测什么

它每天盘后对每个持仓回答：

> 如果明天开盘卖出，和继续持有相比，哪个更划算？

它只用收盘后可见数据，动作只能是：

- 继续持有。
- 次日开盘卖出。

不使用盘中 L2，不要求白天盯盘。

### 3.3 它的输入

对每个持仓，每天盘后构造持仓状态：

- 当前浮盈/浮亏。
- 持仓天数。
- 持仓以来最大冲高。
- 当前收盘价相对最高点回撤。
- 持仓以来最大回撤。
- 最近 3/5 日收益。
- 当日 L2 主力净流、超大单净流。
- 持仓期间累计资金净流。
- 热点主题是否还强。
- 市场环境是否支持。
- 是否涨停、炸板、出货风险。

### 3.4 v0.2 为什么多了“强势续拿模型”

第一版卖点模型已经比固定 15%止盈好，但仍有较高卖飞率。

所以 v0.2 加了一个辅助模型：

> 当主卖点模型想卖时，再判断这只票后面是否还有明显额外空间。如果续拿模型认为还有空间，就暂缓卖出。

这就是 `guard` 逻辑。

### 3.5 当前保留的两个组合

#### 星火进攻版

ID：`spark_aggressive`

组合：

- 买入：星火机会模型 top1 + 条件 top2
- 卖出：守势持仓模型 `pc_model_th6_stop12`

验证：

| 指标 | 数值 |
|---|---:|
| 连续账户收益 | +144.23% |
| 最大回撤 | -11.23% |
| 交易数 | 51 |
| 胜率 | 62.75% |
| 平均持仓 | 5.04 天 |
| 卖飞率 | 58.82% |
| 平均少拿 | 7.14pct |

特点：

- 月度贡献更均衡。
- 收益更高。
- 交易更多。
- 卖飞仍多，但账户结果最好。

#### 星火稳健版

ID：`spark_guarded`

组合：

- 买入：星火机会模型 top1
- 卖出：守势持仓模型 `pc_model_th6_guard12_stop12`

验证：

| 指标 | 数值 |
|---|---:|
| 连续账户收益 | +134.74% |
| 最大回撤 | -17.14% |
| 交易数 | 24 |
| 胜率 | 70.83% |
| 平均持仓 | 7.08 天 |
| 卖飞率 | 33.33% |
| 平均少拿 | 2.91pct |

特点：

- 卖飞明显减少。
- 胜率更高。
- 但收益高度依赖少数大票。
- 不适合作为唯一主方案。

### 3.6 为什么当前更推荐进攻版做主线

收益集中度：

| 版本 | 最大单笔贡献 | 前 3 笔贡献 | 前 5 笔贡献 |
|---|---:|---:|---:|
| 星火进攻版 | 25.06% | 58.81% | 77.85% |
| 星火稳健版 | 56.31% | 87.29% | 97.53% |

稳健版看起来更“稳”，但利润过度来自少数样本。进攻版虽然卖飞更多，但收益来源相对分散，更适合继续做风险约束。

## 4. 和现有选股工作台怎么衔接

当前工作台已有这些入口：

- 每日复盘决策
- 资金流回调稳健
- 趋势中继高质量回踩
- 旧策略对照

星火模型不应该替代它们，而应该作为新的候选来源进入同一个候选池。

### 4.1 推荐的候选池结构

每天盘后生成一个统一候选表：

| 字段 | 含义 |
|---|---|
| `trade_date` | 信号日期 |
| `symbol` | 股票代码 |
| `name` | 股票名称 |
| `source_type` | `model` / `rule_strategy` / `hot_theme` / `manual_watchlist` |
| `source_id` | 例如 `spark_opportunity_selector`、`stable_capital_callback` |
| `source_name` | 星火机会模型、资金流回调稳健 |
| `rank` | 来源内部排序 |
| `score` | 来源内部评分 |
| `horizon` | 预期周期，例如 `22d`、`5d`、`event` |
| `suggested_action` | `watch` / `candidate_buy` / `hold` / `sell_next_open` |
| `buy_rule` | 次日买入条件 |
| `risk_tags` | 风险标签 |
| `explain_factors` | 可解释因子 |
| `model_version` | 模型版本 |
| `artifact_path` | 结果来源文件或模型目录 |

这样以后新增模型，不需要改工作台逻辑，只要新增一个 `source_id`。

### 4.2 页面上建议怎么展示

每天晚上打开工作台时，左侧不再只是一组策略 tab，而是一个“今日候选池”：

- 全部
- 模型
- 老策略
- 热点主题
- 自选观察

每只票显示来源徽标：

- `星火机会`
- `资金流回调`
- `趋势中继`
- `热点主题`
- `人工观察`

如果同一只票被多个来源命中，应该合并成一张卡，并显示：

- 命中来源数。
- 哪些来源命中。
- 是否与热门主题共振。
- 是否已有持仓。
- 是否仓位已满。

### 4.3 你每天实际怎么用

盘后流程：

1. 更新数据。
2. 星火机会模型产出明日候选。
3. 老策略产出候选。
4. 热点主题产出主线/题材方向。
5. 工作台合并候选。
6. 守势持仓模型扫描当前持仓，生成卖出/继续持有建议。
7. 你人工看候选和持仓建议。

次日开盘流程：

1. 如果仓位没满，看 `candidate_buy`。
2. 优先看多来源共振的票。
3. 星火机会票遵守买入约束：高开不超过 6.8%，且不接近涨停。
4. 如果仓位已满，不强行买新票。
5. 若守势持仓模型给出 `sell_next_open`，可以腾出仓位。

盘后持仓流程：

1. 系统读取当前持仓。
2. 对每个持仓计算今日收盘后的持仓特征。
3. 守势持仓模型输出：
   - `hold`
   - `sell_next_open`
   - `watch_risk`
4. 次日开盘按建议处理。

## 5. 多模型并存时怎么判断用哪个

未来不要只比较“收益最高”。每个模型都要有画像。

建议每个模型登记这些字段：

| 字段 | 例子 |
|---|---|
| 模型名 | 星火机会模型 |
| 模型 ID | `spark_opportunity_selector` |
| 目标 | 22 日冲高机会 |
| 输入 | 盘后日线 + L2 聚合 + 热点 + 市场环境 |
| 输出 | 次日候选 top1/top2 |
| 周期 | 22 个交易日 |
| 风格 | 进攻、短线冲高 |
| 适合行情 | 题材活跃、强势票有延续 |
| 不适合行情 | 普跌、缩量、热点退潮 |
| 主要风险 | 卖飞、回撤、收益集中 |
| 当前状态 | 研究可用，未投产 |

模型之间的判断方式：

1. **同票多模型命中**：优先级提高。
2. **模型命中 + 热点主题共振**：优先级提高。
3. **模型命中但主题退潮/高开过大/涨停买不到**：降级为观察。
4. **老策略命中但星火不命中**：可以看，但不要自动提高仓位。
5. **星火命中但老策略不命中**：按模型票处理，需要看买入约束。

## 6. 当前应该保留/归档的实验

### 保留

| 名称 | ID | 用途 |
|---|---|---|
| 星火机会模型 | `spark_opportunity_selector` | 主选股模型 |
| 守势持仓模型 | `sentinel_postclose_exit` | 盘后持仓卖点 |
| 星火进攻版 | `spark_aggressive` | 当前主研究组合 |
| 星火稳健版 | `spark_guarded` | 对照组合，少卖飞 |

### 归档

| 实验 | 原因 |
|---|---|
| 固定 15% 止盈 | 卖飞严重，只做基准 |
| 固定 22 日持有 | 回撤和资金占用不可控，只做上限/下限参考 |
| 早盘 5 分钟买点模型 v0.1 | 有价值，但不符合你“不盯盘、盘后决策”的主工作流 |
| H5 短周期模型 | 可作为未来短线模型参考，当前不作为主线 |
| top2 + guard 强续拿 | 拖累收益，说明 top2 质量不稳定 |

## 8. 当前限制

1. 数据时间短：主要覆盖 2025-01 到 2026-05。
2. 4 月以后成熟标签不足，因为 22 日窗口需要未来数据。
3. 收益仍有集中度问题。
4. 当前还没有接入真实持仓账户状态。
5. 当前还没有把模型结果写入工作台统一候选表。
6. 当前模型解释是“特征贡献/标签设计层面的解释”，不是树模型逐笔 SHAP 解释。

## 9. 下一步落地建议

优先级从高到低：

1. 建统一模型候选表，让星火机会模型进入选股工作台。
2. 建持仓输入表，记录你真实/模拟持仓。
3. 每天盘后跑守势持仓模型，输出 `hold / sell_next_open`。
4. 工作台左侧合并老策略、星火模型、热点主题。
5. 同票多来源命中时做加权排序。
6. 给每个模型候选补解释字段和风险标签。
7. 做模拟盘，不直接实盘。

最低可用版本只需要三个表：

1. `model_candidate_daily`
2. `model_position_daily`
3. `model_action_daily`

这样后面训练新模型时，只要继续往这三张表写结果，工作台不需要重做。

## 10. 生产判断

当前状态：**研究可用，不建议无脑实盘。**

可以做：

- 每天作为候选来源参考。
- 和老策略、热点主题交叉验证。
- 模拟盘记录真实执行。
- 小仓位人工验证。

不建议做：

- 满仓自动买。
- 完全自动卖。
- 只看模型 top1 不看开盘条件。
- 用 3 月收益外推长期收益。
