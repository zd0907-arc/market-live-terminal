# 研究 worktree 生命周期规则

更新时间：2026-06-04

## 结论

`worktree` 只是一次研究任务的临时容器，不是项目长期结构的一部分。

原则固定为：

1. 少开
2. 单题
3. 快收

以后做模型研究，目标不是保留很多活着的 worktree，而是：

- 需要隔离时才开
- 一次只承接一个明确方向
- 研究结果按文档治理规则收口后，马上删除

## 1. 什么时候才允许新开 worktree

满足任一条件才建议开：

1. 会改动较多代码或文档，不适合直接放主工作区
2. 需要并行推进另一个独立方向
3. 需要长时间跑训练、回测、页面开发，容易和主线互相污染

如果只是：

- 看文档
- 做轻量分析
- 补少量记录

那不要为了形式专门开一个新 worktree。

## 2. 一个 worktree 只承接一个主题

推荐规则：

- 一个 worktree = 一个主题
- 一个主题 = 一个明确目标

例如：

- 星火 v2 纯选股
- 次日 / 超短
- 热点预筛
- 试盘识别

不要把：

- 训练
- 页面
- 数据治理
- 热点研究

长期混在同一个研究 worktree 里。

## 3. 开始前必须先定三件事

在创建 worktree 前，先写清楚：

1. 研究目标
2. 退出条件
3. 结果收口方式

## 4. 研究进行中的最小产物

一个活跃 worktree 在研究过程中，至少要能产出：

1. 一份方向说明或训练计划
2. 一轮或多轮实验结果
3. 一份业务结论

## 5. 收口时必须做什么

研究准备关闭 worktree 时，必须完成下面 checklist：

1. 结论是否已经写成文档
2. 结果是否已经放入正确层级
3. 是否需要更新：
   - `docs/model-research/research-directions-index.md`
   - `docs/model-research/current-material-map.md`
   - 对应方向状态卡
4. 是否有应该归档的实验目录
5. 是否需要保留到产品接入层

只有这 5 项完成，才算允许删 worktree。

## 6. 收口后的正确动作

研究结束后，正确顺序是：

1. 把必要代码 / 文档合回主线或指定分支
2. 把方向状态卡和索引更新掉
3. 把实验产物放到长期可追溯的位置
4. 删除 worktree

不要把 worktree 当长期仓库。
