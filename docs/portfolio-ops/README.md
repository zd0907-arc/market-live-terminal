# 持仓操盘跟踪

## 定位

这个目录记录人工实盘持仓、每日系统信号、候选替换评估、操作复盘和分析方法迭代。

它不是新的选股模型，也不替代 `Selection Research` 工作台；它是持仓决策层，负责把已有模块和外部信息合成每天的操作建议。

## 每日工作流

1. 更新当前持仓：仓位、成本、当日是否操作。
2. 检查数据新鲜度：确认原子库、选股库、热点数据最新日期。
3. 读取当前持仓数据：日线、多周期、L2、OIB/CVD、盘口、选股信号、退出风险。
4. 读取新候选：星火模型、两个策略、统一候选池、风险拦截、退出观察池。
5. 读取热点：细分板块热度、热点预测、持仓与候选所属主题。
6. 查外部信息：指数环境、重大宏观、行业新闻、公司公告。
7. 做组合比较：当前持仓继续拿的理由 vs 新候选换仓的理由。
8. 输出动作：不动、减仓、换仓、加仓，并给触发条件。
9. 用户晚上反馈实际操作后，写入操作记录和次日跟踪重点。

## 决策原则

- 先判断原持仓逻辑是否失效，再判断新机会是否足够强。
- 日内资金和挂单只做次日执行参考，不单独决定周/月级持仓。
- 不因为一天弱就卖，不因为一天强就追。
- 换仓必须证明新标的的预期收益、确定性或风险收益比明显优于当前持仓。
- `不动` 是正式动作，不是没结论。

## 文件

- `current-portfolio.md`：当前持仓、买入逻辑、仓位和跟踪重点。
- `daily-review-template.md`：每天复盘和次日计划模板。
- `module-map.md`：系统内各模块怎么用于操盘判断。
- `agent-architecture.md`：持仓操盘 Agent 的分工、输入输出和落地顺序。
- `execution-plan.md`：如何真正执行这些 Agent 分工、何时使用子 Agent、后续如何 skill 化和自动化。
- `company-cards/`：每只实盘持仓的公司研究卡。
- `method-log.md`：新发现的分析技巧、规则和反例。
- `trade-log.md`：用户实际买卖记录。
