# 持仓操盘 Agent 架构

## 目标

把当前项目里的行情、L2、选股、热点、模型、外部新闻和公司基本面研究组织成一套可持续复用的操盘分析流程。

核心目标不是自动下单，而是每天给出更可信的持仓判断、换仓比较和次日计划。

## 参考逻辑

Anthropic 金融 Agent 的可借鉴点：

- 用专门 Agent 处理不同金融任务，而不是一个大模型一次性回答所有问题。
- Agent 由技能说明、数据连接器、子任务 Agent 组成。
- 每个结论要能追溯到数据源、工具调用和方法。
- 人保留最终审核和批准权。

适合本项目借鉴的方向：

- Market Researcher：行业、主题、宏观和市场主线研究。
- Earnings / Company Research：公司业务、财报、业绩驱动因素研究。
- Financial Modeling：利润驱动因素、估值、关键假设和敏感性分析。
- Valuation Reviewer：估值和逻辑复核。
- Methodology Check：检查结论是否由数据支持，避免单日波动过度决策。

不适合直接照搬的方向：

- KYC、总账、月结、审计、投行 Pitchbook、客户会议准备等偏机构流程，当前不作为主线。

## Agent 分工

### 1. Portfolio Orchestrator

总控 Agent。负责聚合所有子 Agent 的结论，输出最终组合动作。

输入：

- 当前持仓、仓位、成本、买入原因。
- 当天系统数据日期。
- 用户当日操作反馈。

输出：

- 组合动作：不动 / 减仓 / 加仓 / 换仓。
- 每只票的核心理由、风险和触发条件。
- 是否需要更新方法日志。

### 2. Data Freshness Agent

检查数据是否完整。

职责：

- 确认原子库、选股库、模型特征库、热点库最新日期。
- 识别旧库、空库、未合并 delta。
- 标记哪些分析只能按旧日期做。

### 3. Position Thesis Agent

维护每只持仓的买入逻辑。

职责：

- 记录买入来源：模型、策略、人工判断、热点驱动。
- 记录目标周期和失效条件。
- 判断今天的数据是否推翻原持仓逻辑。

### 4. Company Research Agent

做公司研究。

职责：

- 公司主营业务、收入构成、利润构成。
- 最近财报变化：收入、利润、毛利率、现金流、存货、应收。
- 利润驱动因素：价格、销量、产能、订单、租赁率、费用率。
- 估值锚：PE、PB、市值、同业对比、利润弹性。
- 重大公告、问询、减持、回购、股权激励、业绩预告。

输出必须包括：

- 这个公司靠什么赚钱。
- 哪些变量最影响股价。
- 最近一个季度验证了什么，否定了什么。
- 哪些新闻是实质利好，哪些只是情绪。

### 5. Industry / Theme Agent

做行业和主题研究。

职责：

- 持仓和候选分别属于哪些细分板块。
- 当前热点强度、持续性、拥挤度和退潮风险。
- 行业政策、供需、价格、库存、订单、竞争格局。
- 板块内龙头、跟风、补涨和掉队关系。

### 6. News / Event Agent

做每日新闻监控。

职责：

- 公司公告。
- 行业新闻。
- 政策和宏观事件。
- 外盘、港股、商品、汇率等相关线索。
- 对每条新闻标注：利好 / 利空 / 中性 / 噪音，影响周期和确定性。

### 7. Technical / Microstructure Agent

分析行情和微观资金。

职责：

- 日线、5m、30m 趋势。
- L2 主力、超大单、L1。
- OIB、CVD、主动买卖。
- 委买委卖、盘口不平衡、尾盘承接。
- 区分执行信号和持仓逻辑。

### 8. Candidate / Model Agent

分析系统新推荐。

职责：

- 星火模型。
- 两个策略。
- 统一候选池。
- 风险拦截、退出观察。
- 新候选和当前持仓做横向比较。

### 8.1 Spark Validation Agent

专门跟踪星火机会模型买入后的验证仓。

职责：

- 查星火信号日、排名、分数、原因、风险标签。
- 按 22 个交易日窗口跟踪最高涨幅和最大回撤。
- 跟踪是否达到 15% 冲高目标。
- 查守势持仓模型是否给出继续持有或次日卖出。
- 不用单日弱强否定模型仓。

### 9. Portfolio Risk Agent

控制组合风险。

职责：

- 单票仓位是否过重。
- 题材暴露是否过度集中。
- 当前回撤和流动性。
- 是否需要腾仓。
- 换仓是否真的改善风险收益比。

### 10. Backtest / Method Agent

负责把新方法沉淀为可验证规则。

职责：

- 把聊天中发现的规则写入 `method-log.md`。
- 设计回测问题。
- 对比持有、减仓、换仓、加仓的历史效果。
- 标记规则的失败反例。

## 每日输出格式

每个子 Agent 的输出都必须短，但要结构化：

```json
{
  "agent": "Company Research",
  "symbol": "sz002600",
  "view": "hold",
  "confidence": "medium",
  "key_evidence": ["证据1", "证据2"],
  "risk": ["风险1"],
  "needs_follow_up": ["待查事项"]
}
```

总控 Agent 最后只给：

- 组合结论。
- 每只持仓动作。
- 新候选是否值得替换。
- 明日触发条件。
- 需要更新的记录。

## 持仓研究卡

每只新买入股票必须建立一张公司研究卡，建议路径：

```text
docs/portfolio-ops/company-cards/{symbol}-{name}.md
```

最低字段：

- 买入日期：
- 买入来源：
- 当前仓位：
- 主营业务：
- 收入/利润构成：
- 最近财报：
- 估值锚：
- 股价核心变量：
- 正面催化：
- 负面催化：
- 持有条件：
- 失效条件：
- 每日跟踪关键词：

## 实施顺序

1. 先给当前三只持仓补公司研究卡。
2. 每天复盘时强制跑 Data Freshness、Technical、Candidate、Theme 四类。
3. 对重仓票强制跑 Company、News、Risk。
4. 出现新买入后，当天晚上补公司研究卡。
5. 每周用 Backtest / Method Agent 复核本周决策是否有效。
