## 2. 这份文档现在回答什么

这份文档不是“删除命令清单”，而是先把运行产物讲清楚：

1. 哪些东西只是跑数过程产物，不是正式数据。
2. 它们分别在支撑什么页面、验证或排障动作。
3. 什么时候可以清，什么时候绝对不能碰。
4. 你前面提到的 `snapshot`、`local research`、`market heat cache` 到底分别是什么。

当前阶段不执行删除，只定义保留和后续执行边界。

## 3. 先讲原则

1. 运行产物不等于正式真相源。
2. 看起来“很大”的文件，不一定该删；看起来“像正式库”的文件，也可能只是缓存或快照。
3. 历史跑数还没结束的批次，一律不碰。
4. 判断能不能动，先看它影响哪个页面/功能，再看技术路径。

## 5. 你前面点名的 3 类对象，到底是什么

### 5.1 `snapshot / local research`

这类东西不是正式主库，而是“本地研究站快照”。

业务上它的作用是：

1. 让 Mac 本地研究站不用每次都直接去啃完整正式大库。
2. 让 Windows 跑完一轮以后，可以同步一份适合本地研究的快照过来。
3. 让你做页面验证、功能验证时，有一份相对稳定的本地视图。

所以这类对象的问题不是“有没有必要存在”，而是“要不要积累很多份历史版本”。当前建议是只保留：

- 当前在线使用的 1 份
- 最近一个可回退点

### 5.2 `market heat cache`

这类东西不是热点正式真相源，而是“热点页面缓存”。

业务上它的作用是：

1. 热点页和热点脚本不用每次都从头重算。
2. 直接复用最近一个已经可用的窗口，加快展示和验证。

所以它不能一刀切删掉，但也不该无限堆积。当前建议是：

- 保留当前页面实际在用的最新窗口
- 再保留少量关键历史窗口
- 旧窗口转归档，而不是一直堆着

### 5.3 Windows 月批 / 回传目录

这类东西是“批量跑数现场”。

业务上它的作用是：

1. 记录某个月或某一批历史重跑是否成功。
2. 让你在还没跑完全年数据之前，能知道当前进度和失败位置。

所以在你现在还在持续跑数的阶段，这类目录不能碰。要等到：

1. 当前批次明确结束
2. 关键结论已经写回文档
3. 至少保留最后一次成功摘要

之后，才能考虑压缩和归档。

## 6. 什么时候可以动，什么时候不能动

### 6.1 现在绝对不要动的

1. 当前仍在跑的 Windows 月批/回传目录
2. 当前页面正在用的热点缓存最新窗口
3. 当前在线使用的本地研究站快照
4. 当前最新一轮日跑的状态摘要

### 6.2 可以进入后续治理候选，但不是现在删的

1. 历史 `.pid`、`.lock`、旧日志
2. 已完成批次的旧 `report.json`、旧 `validation_*.json`
3. 已 merge 且已校验通过的 `day_delta_*.db`
4. 非当前窗口的热点旧缓存
5. 多余的本地研究站 `.bak.*` 快照

## 7. 运行产物的业务化执行门槛

后续任何一次清理，至少满足以下 5 条里的 4 条：

1. 已有更新的成功运行窗口。
2. 当前页面或功能不再依赖该对象。
3. 关键结论已经回写文档，不再靠原始产物解释。
4. 当前没有活跃 worktree / AI 会话还在引用它。
5. Windows 与 Mac 两端都确认这一批次已经收口。

## 8. 技术附录：建议保留周期

| 对象族 | 建议保留 |
|---|---|
| 日跑状态摘要 | 最近 `7~14` 个交易日 |
| 当前历史批次目录 | 到该批次结束 |
| `day_delta_*.db` 这类中间增量库 | `3~7` 天 |
| 热点缓存 | 当前最新 + 少量关键历史窗口 |
| 本地研究站快照 | 当前在线 1 份 + 最近回退点 |
| 日志、`.pid`、`.lock` | 当前运行/排障窗口 |
| `*_validation*` / `*_smoke*` | 阶段收口后归档或清理 |

## 9. 当前最重要的结论

1. 现在最需要的是控量和分层，不是清空。
2. `snapshot / local research` 是快照，不是正式真相源。
3. `market heat cache` 是页面缓存，不是热点正式主库。
4. Windows 月批与回传目录是当前跑数现场，在你跑数没结束前不能碰。
5. 真正能先处理的，通常是旧日志、旧 `.pid`、旧 `day_delta` 和多余快照备份。
